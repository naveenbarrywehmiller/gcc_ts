# Task Ownership Details

Ownership entries remain managed under **Departments → Ownership Details**. Productive tasks must select one entry through the **Ownership Details** dropdown; Non-Productive tasks may leave it blank. The dropdown shows the Department name alongside the label. Task permissions remain unchanged: Admins and System Admins maintain tasks; Managers and System Admins maintain Department ownership entries.

Task create/update requests use optional `ownership_id` for Non-Productive tasks and required `ownership_id` for Productive tasks, a positive integer or numeric ID string. A new selection must reference an active ownership entry in an active Department. Responses from `/api/tasks` and task create/update include `ownership_id`, `ownership_label`, and `ownership_department_name`. Partial updates retain an existing assignment; clearing it is rejected for Productive tasks and allowed for Non-Productive tasks. An existing inactive assignment may be retained but cannot be assigned to another task.

Startup adds a nullable foreign key without guessing ownership for existing tasks. Unassigned tasks display **Not assigned** and require a selection at their next save or import only when classified Productive. This task metadata does not rewrite ownership recorded on historical timesheets or change the existing timesheet ownership selection.

Exported task workbooks include an **Ownership Details** dropdown. Values display `ID — Department — Ownership label`; the stable ID identifies the entry when importing, even if its display text was subsequently renamed. CSV imports may use the numeric ID in `Ownership Details` or `ownership_id`. Productive rows require a valid ownership selection; Non-Productive rows may leave it blank or omit the ownership column. Old templates can be re-exported to obtain the choices. Missing Productive ownership, invalid values, or newly assigned inactive choices reject the entire import without changing tasks, omitted rows, or audit records. Existing signed export IDs and omission/deactivation behavior remain in effect.
